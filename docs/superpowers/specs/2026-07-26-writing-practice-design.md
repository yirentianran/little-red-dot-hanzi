# 汉字描写练习功能设计

日期：2026-07-26

## 1. 目标

在现有离线汉字学习页中增加描写练习，让儿童在学习拼音、组词和小红点笔顺动画后，通过鼠标、触屏或手写笔按规范笔顺书写汉字，并获得逐笔反馈。

练习同时覆盖“会写”和“会认”两类汉字，支持从单字页练当前字，也支持从课文页连续练习当前分类的全部汉字。应用在本机保存汉字掌握状态和课文练习进度，不引入账号、云同步或在线服务。

## 2. 设计原则

- 保留现有学习体验：小红点动画、逐笔控制和发音功能不因练习功能而改变。
- 使用成熟判断引擎：练习判定使用 Hanzi Writer Quiz，不自行实现完整的笔画匹配算法。
- 完全离线：运行时不访问 CDN、接口或远程字形数据，继续支持 `file://` 直接打开。
- 儿童优先：每次只关注一个汉字和一项明确操作，反馈短而具体，不使用百分制。
- 容错但不含糊：输入中断不计错；完成的笔画必须满足笔顺、方向和形状要求。
- 状态分层：汉字书写能力全局共享，课文分类的练习完成情况单独记录。

## 3. 范围

### 3.1 包含

- “会写”和“会认”字表的“练习本组”入口。
- 两类单字页的“练习这个字”入口。
- 引导描写和独立描写两个阶段。
- 每笔抬起后的正确或错误反馈。
- 当前笔起点提示、错误重试和连续错误后的笔画提示。
- 当前字重写、稍后再练和结果页未掌握字重练。
- 全局汉字掌握状态、练习次数和最近结果。
- 课文与分类维度的完成进度和中断恢复。
- 鼠标、触屏和手写笔输入。
- 手机、平板和桌面响应式布局。

### 3.2 不包含

- 书写过程中实时检测偏离并强制回到轨迹。
- 整字自由书写识别或字形美观度评分。
- 百分制、排行榜、奖励系统或连续签到。
- 用户账号、云同步、跨设备同步和详细历史统计页。
- 教师端、练习内容编辑器或新的教材数据。

## 4. 技术方案

采用学习与练习分离的混合方案。

### 4.1 学习动画

现有 `svg-renderer` 和 `animation-controller` 继续负责单字学习页：

- 规范笔画轮廓揭示。
- 沿当前笔画前端移动的小红点。
- 连续循环与单笔播放。
- 暂停、重播、上一笔、下一笔和三档速度。

现有渲染器不接收用户笔迹，也不依赖 Hanzi Writer 的运行时对象。

### 4.2 描写练习

固定使用本地 `hanzi-writer@3.7.3` 浏览器构建。浏览器脚本和 MIT 许可声明随项目分发，不从 CDN 加载。Hanzi Writer 只在练习页实例化，并通过同步 `charDataLoader` 从现有数据仓库返回当前字的 `strokes` 和 `medians`。

当前字形数据已满足 Quiz 的必要输入。`radStrokes` 是 Hanzi Writer 的可选字段，项目无需恢复提取时移除的部首笔画标记。项目自有的 `strokeCount` 不传给判断引擎。

### 4.3 适配层

新增 `practice-engine` 作为 Hanzi Writer 与应用之间的唯一边界。它提供以下命令：

- `start(options)`：以引导或独立阶段开始当前字。
- `restart()`：清除当前字并从第一笔重写。
- `showHint()`：播放当前规范笔画提示。
- `cancel()`：取消当前 Quiz 和未完成笔迹。
- `destroy()`：移除实例、监听器和渲染节点。

它只向上层发布以下事件：

- `stroke-correct`
- `stroke-mistake`
- `stroke-hint`
- `character-complete`

事件数据包含当前笔序号、当前笔错误次数、整字累计错误次数、剩余笔画数、标准化后的用户笔迹 `drawnPath`，以及 Hanzi Writer 提供的方向错误标记。视图和会话控制器不得读取 Hanzi Writer 私有字段。

### 4.4 练习提示叠加层

Hanzi Writer 不直接提供本设计所需的当前笔起点红点和红色错误笔迹。练习页在 Quiz SVG 上方增加一个不接收指针事件的 SVG 叠加层：

- 会话控制器维护当前笔序号。
- 起笔红点取当前 `medians[strokeIndex][0]`，使用与 Quiz 相同的缩放和坐标变换。
- 错误事件使用公开回调返回的 `drawnPath`，在叠加层短暂绘制红色错误轨迹。
- 叠加层设置 `pointer-events: none`，不得阻断 Hanzi Writer 的输入处理。
- 页面尺寸变化时，Quiz 与叠加层使用同一尺寸源更新，避免位置漂移。

以上效果只依赖公开回调和现有字形数据，不读取或修改 Hanzi Writer 私有渲染状态。

### 4.5 会话控制器

新增练习会话控制器，负责：

- 单字或整组练习队列。
- 当前汉字与当前位置。
- `guided`、`independent`、`needs-retry` 和 `complete` 阶段。
- 错误计数、提示触发和掌握判定。
- 立即重练或加入本轮未掌握列表。
- 进度保存、恢复和结果汇总。

控制器不渲染 DOM，也不直接接收指针事件。

## 5. 路由与入口

新增 `practice` 路由，逻辑结构为：

```text
#/practice?lesson=lesson-1&group=write&scope=group&character=潮
```

- `lesson` 必须是存在的课文或语文园地。
- `group` 必须为 `write` 或 `recognize`。
- `scope` 必须为 `single` 或 `group`。
- `character` 必须属于指定课文和分类。

阶段不写入 URL，由练习存储恢复。直接访问一个合法练习 URL 时，若没有可恢复阶段，未掌握字从引导阶段开始，已掌握字从独立阶段开始。

整组练习内部切换汉字时使用替换历史记录的方式更新 `character`，避免每个汉字占用一条浏览器历史。浏览器返回应离开练习并回到进入前的字表或单字页。

非法练习路由按以下顺序回退：

1. 课文无效：回到课程目录。
2. 分类无效或为空：回到该课默认可用分类的字表。
3. 汉字无效：整组练习使用该分类第一个字，单字练习回到字表。

## 6. 练习流程

### 6.1 阶段选择

- 尚未掌握的字：先完成引导描写，再完成独立描写。
- 已在其他课文或分类掌握的字：当前练习直接进行独立描写。
- 单字练习和整组练习使用相同规则。

### 6.2 引导描写

- 显示浅色完整字形轮廓。
- 显示当前笔起点红点。
- 用户抬笔后由 Quiz 判断当前笔。
- 正确笔画保留为近黑色，并进入下一笔。
- 错误笔迹变红后淡出，停留在当前笔重写。
- 同一笔连续错误两次后自动播放该笔提示。
- 引导阶段的错误不影响掌握判定。

### 6.3 独立描写

- 隐藏完整字形轮廓。
- 只显示当前笔起点红点和已正确完成的笔画。
- `acceptBackwardsStrokes` 固定为 `false`。
- 所有笔画首次写对，即本轮零错误完成，标记为“已掌握”。
- 任一笔出现错误时，仍允许完成整字；完成后标记为“需要再练”。
- “需要再练”可立即重做独立阶段，也可加入本轮未掌握列表并继续下一个字。

### 6.4 错误反馈

Hanzi Writer 在抬笔后判断，不在移动过程中中断书写。

- 方向相反：提示“方向反了，再试一次”。
- 其他错误：提示“这一笔不对，再试一次”。
- 输入被浏览器取消、第二根指针加入或指针异常离开：取消当前笔，不计为错误。
- 不依据公开回调无法区分的原因显示“起点错误”或“偏离轨迹”等过度具体提示。

### 6.5 整组队列

- 初始顺序与当前课文分类的字表顺序一致。
- 每个字完成后自动进入下一个字。
- 本轮每个字最多进入队列一次；选择“稍后再练”会把当前字加入本轮未掌握列表并继续下一个字，不改变其他字顺序。
- 结果页的“再练未掌握字”使用本轮未掌握列表创建一个新队列和新一轮练习。
- 中途退出时保存当前字、剩余队列和阶段；再次进入后从该阶段开头恢复，不恢复半笔或半个字的笔迹。

### 6.6 完成结果

整组完成后在练习页面内显示结果，不使用弹窗。结果包含：

- 本次练习字数。
- 本次新掌握字数。
- 当前已掌握字数。
- 需要再练字数。
- “再练未掌握字”和“返回字表”命令。

## 7. 页面设计

### 7.1 字表页

- 在“会写 / 会认”分段控件下显示“练习本组”主按钮。
- 同一区域显示“本组已完成 X / Y”和当前掌握数量。
- 汉字方格使用小型对勾表示全局已掌握，并提供等价的可访问名称。
- 全局已掌握不等于当前课文已完成；进入本组后仍需独立练习一次才计入本组完成。

### 7.2 单字页

- “会写”和“会认”单字页都显示“练习这个字”。
- 入口靠近现有读音与笔顺控制区域，不覆盖米字格。
- 离开练习返回单字页后，学习动画根据原有分类规则恢复。

### 7.3 练习页

练习页顶部显示返回命令、课文与分类、当前汉字位置、汉字、拼音和当前阶段。米字格是主视觉区域。

桌面和横屏平板使用米字格加窄工具栏的双列布局；手机和竖屏平板使用单列布局。米字格始终保持正方形比例，反馈文字变化不得改变其尺寸。

工具栏包含：

- 当前笔和总笔画数。
- 固定高度的反馈区域。
- 提示、重写和稍后再练命令。
- 本字笔画进度。

视觉规则：

- 起笔点使用品牌红色。
- 用户正在书写的笔迹使用深蓝色。
- 正确完成笔画使用近黑色。
- 错误笔迹使用红色并淡出。
- 练习区域不放入装饰性卡片。
- 操作目标不小于 44 × 44 CSS 像素。
- 图标按钮具有工具提示和准确的中文可访问名称。

书写区域设置 `touch-action: none`，仅拦截米字格内的书写手势；页面其他区域保持正常滚动。

## 8. 数据与持久化

新增独立存储键 `hanzi-tracking:practice-progress:v2`，与现有最近学习位置分开。

逻辑结构：

```json
{
  "schemaVersion": 2,
  "characters": {
    "潮": {
      "attemptCount": 3,
      "lastOutcome": "mastered",
      "mastered": true
    }
  },
  "groups": {
    "lesson-1:write": {
      "completedCharacters": ["潮", "据"],
      "roundCharacters": ["潮", "据", "堤", "阔"],
      "roundCompletedCharacters": ["潮", "据"],
      "remainingCharacters": ["堤", "阔"],
      "needsPracticeCharacters": ["据"],
      "roundInitialMasteredCharacters": ["潮"],
      "roundNewlyMasteredCharacters": [],
      "currentCharacter": "堤",
      "currentPhase": "guided"
    }
  }
}
```

### 8.1 全局汉字记录

- 以单个汉字为键，不区分课文、分类或读音。
- `attemptCount` 在每次独立描写完成后增加。
- `lastOutcome` 为 `mastered` 或 `needs-practice`。
- 独立阶段零错误完成时，`mastered` 设为 `true`。
- 已掌握字后来独立练习出现错误时，`mastered` 降为 `false`。
- 多音字共享字形掌握状态，但页面继续显示当前教材条目的拼音、组词和发音。

### 8.2 课文分类记录

- 以 `lessonId:group` 为键。
- 单字练习完成后，同样把该字加入对应课文分类的 `completedCharacters`。
- `completedCharacters` 是跨轮次累计完成记录；`roundCharacters` 及其他 `round*` 字段只描述当前一轮，筛选重练不会缩小累计记录。
- `roundInitialMasteredCharacters` 固定记录开轮时已经掌握的字，`roundNewlyMasteredCharacters` 记录本轮新掌握的字，用于恢复后仍能准确汇总结果。
- `remainingCharacters`、`needsPracticeCharacters`、`currentCharacter` 和 `currentPhase` 支持中断后恢复当前队列与阶段。
- 完成记录表示该课文位置已经练过，不要求当前仍为全局已掌握。
- 字表同时显示“已完成练习”和“当前掌握”两个不同统计。

### 8.3 写入与恢复

- 只在一笔结束、阶段切换、汉字切换和退出时写入，不在指针移动过程中写入。
- 独立描写结果与对应轮次进度通过一次事务写入，页面不会观察到只更新其中一层的中间状态。
- 存储解析采用严格版本和字段校验。
- 数据损坏或版本不支持时只重置练习进度键。
- `localStorage` 不可用或写入失败时切换为内存状态，练习继续可用，并显示“本次进度不会保存”。

## 9. 生命周期与异常处理

- 进入新字前销毁上一字的 Quiz 实例。
- 路由切换、页面销毁和重新开始时先调用 `cancelQuiz()`，再移除监听器和节点。
- 会话使用递增版本号隔离异步回调；旧实例的回调不得改变新页面。
- 页面尺寸变化时更新练习画布尺寸，不重启当前字。
- 多点触控只保留第一根有效指针，额外指针取消当前笔且不计错。
- 字形数据意外缺失或无法解析时显示“这个字暂时无法练习”，允许跳过或返回。
- 减少动态效果模式下关闭错误笔迹淡出和完成闪烁，但保留明确的文本与颜色反馈。
- 运行时任何练习错误不得破坏学习页、发音、目录或现有最近位置功能。

## 10. 组件与文件边界

建议新增或调整以下模块：

```text
vendor/
  hanzi-writer.min.js
  HANZI_WRITER_LICENSE.txt
js/
  practice-engine.js
  practice-session.js
  practice-progress-store.js
  router.js
  views.js
  app.js
styles.css
index.html
tests/
```

- `practice-engine`：第三方引擎适配、离线字形加载和 Quiz 生命周期。
- `practice-session`：纯状态机、练习队列、阶段和结果汇总。
- `practice-progress-store`：版本化持久化、双层进度和内存降级。
- `router`：解析、序列化和规范化练习路由。
- `views`：渲染入口、练习页和结果页，不注册事件。
- `app`：创建依赖、分发用户命令、协调路由和会话生命周期。

每个模块使用窄接口。第三方对象不得越过 `practice-engine` 边界，存储细节不得进入视图，会话状态不得直接修改 DOM。

## 11. 测试

### 11.1 单元测试

- 适配层正确转换成功、失败、提示和完成回调。
- 离线加载器返回当前字形且不使用网络。
- 引导完成后进入独立阶段。
- 独立阶段零错误才标记掌握。
- 已掌握字跳过引导但仍需独立完成。
- “稍后再练”把当前字加入未掌握列表并继续队列，不丢失或重复汉字。
- 结果页只使用未掌握列表创建新一轮练习。
- 单字练习更新全局记录和当前课文分类完成记录。
- 全局掌握和课文完成可独立变化。
- 存储损坏、版本错误和写入失败安全降级。
- `write` 与 `recognize` 练习路由均可往返序列化。
- 非法路由按规定回退。
- 旧 Quiz 回调不会修改新会话。

### 11.2 笔画匹配验收

选择 8 至 12 个代表性汉字，覆盖点、横折、竖钩、弯钩、撇捺和复杂多笔结构。

- 沿中心轨迹书写应通过。
- 带少量位置抖动的轨迹应通过。
- 反方向书写应失败。
- 跳过当前笔、书写后续笔画应失败。
- 起点明显错误、轨迹明显偏离或笔画过短应失败。
- 容差不能宽到让明显错误笔画通过。

初始使用 Hanzi Writer 默认 `leniency: 1.0`。只有代表性自动测试和真实设备试写共同表明误拒或误收时，才修改集中定义的容差常量。

### 11.3 浏览器验收

- 从“会写”和“会认”字表开始整组练习。
- 从两类单字页开始当前字练习。
- 完成引导、独立、重练、稍后再练和结果流程。
- 刷新后从当前阶段开头恢复。
- 浏览器前进、后退和快速切换不产生重复画布或监听器。
- 通过 `file://` 使用时练习完整可用，网络请求为零。
- 在 360 × 800、768 × 1024 和 1440 × 900 下无横向溢出、遮挡或尺寸跳动。
- 自动化鼠标输入、触屏模拟和真实平板手写笔分别完成一次练习。

### 11.4 无障碍验收

- 所有命令使用原生按钮，具有可见焦点和准确中文名称。
- 正误反馈不只依赖颜色，并由非打断式 live region 宣布。
- 米字格以可访问文本说明当前字、阶段和笔画位置。
- 键盘可以操作练习页除手写本身之外的全部命令。
- 减少动态效果设置生效。

## 12. 验收结果

功能完成时应满足：

1. 学习页现有小红点动画、发音和导航行为无回归。
2. “会写”和“会认”均可进行单字与整组描写练习。
3. 引导与独立两阶段、零错误掌握规则和逐笔反馈符合本设计。
4. 双层进度在刷新和重新打开页面后正确恢复。
5. 所有运行时资源本地可用，`file://` 流程不发起网络请求。
6. 自动测试、代表性笔画测试、响应式截图和真实平板试写全部通过。
